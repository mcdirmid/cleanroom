# pretense interface component

## Purpose

The pretense interface component defines the declarative state machine abstractions, sentinels, collection models, transition specifications, fake adapters, and verification engine contracts for stateful software testing in Cleanroom.

Example-based testing and AST statement coverage frequently miss critical state desynchronizations, boundary regressions, and omitted invariant logic in neural-generated code. By defining stateful systems as executable state transition models rather than static unit test sequences, this component enables automated property-based exploration, invariant checking across arbitrary operation orderings, and automatic fake synthesis. Centralizing these state abstractions prevents fragmentation across test harnesses and ensures that specification contracts remain mathematically verifiable.

**Out of scope:** Subprocess invocation, filesystem scanning, and shell argument parsing; these are handled by other components.

## Types and Behavior

A system's *pretense engine* coordinates state machine compilation, test suite execution, and fake generation.

A *pretense sentinel* distinguishes unprovided inputs and specific runtime states from standard program values. The sentinel *not bound* indicates that a parameter was omitted by a caller. An *execution outcome* encapsulates the result of evaluating an operation against an implementation under test. A *value outcome* wraps a successful return value. A *raised outcome* wraps an expected or intercepted exception instance. A *specification error* indicates that a state machine contract, transition invariant, or antecedent predicate was violated.

A *draw context* provides a dynamically bound generator for sampling values during property-based test exploration. A *pretense collection* provides an observable state container that tracks mutations and verifies invariants. A *pretense dictionary* provides an observable key-value mapping with existence assertions and weighted key selection. A *pretense set* provides an observable unique item container with element sampling and existence assertions.

A *state transition* defines a single atomic operation step within a state machine. Every public method across target interfaces has strictly one corresponding transition method decorated with `@transition(TargetClass.method)` or `@transition.seeding`. The transition method receives the same signature and parameters as the target method, while targets and collaborators under test are accessed via dynamic context scoping `sut(TargetClass)`. Natural branching (`if/else`) and exception contexts (`with raises(ExpectedException):`) express operational branches and contracted errors within a single unified transition. In verification mode, `raises` asserts that the target invocation raises the contracted exception and propagates the exception to callers and property test runners; in Fake mode, `raises` synthesizes and raises an instance of the contracted exception (including structured or multi-argument exception classes) to emulate interface failure semantics. A transition method executes linearly across distinct statement slices:

- A *transition antecedent* enforces gating preconditions using a *requirement assertion* (`requires`) and constrains arguments via *argument requirements* (`require_arg(arg, domain)`). Transition preconditions are extracted statically via AST parsing to gate transition eligibility before execution, and argument requirements define generative domains to sample valid values by construction. At runtime, including when an implementation under test invokes a fake collaborator with an unsatisfied precondition, a precondition failure raises a specification error (or the contracted error) to fail the test immediately. In fixed scenario testing mode, `requires` and `require_arg` accept an optional error argument (passed positionally or via keyword `error`); when the condition fails, the specified error is thrown rather than raising a generic framework violation, enabling fixed scenario tests to verify contracted error outcomes. Pre-state snapshots (`old_*`) and pre-execution invariant assertions (`assert condition`) evaluate before the inner transition invocation.

- An *argument domain* unifies generative sampling with analytical validation for an operation parameter or return outcome, parameterized generically over value types (`Domain[T]`). Combinator argument domains (`list_of`, `set_of`, `mapping_of`, `optional`) preserve constituent element types as generic type parameters. Typed argument domains (`Domain.type(target_cls)`) resolve runtime type constraints across primitive classes and subscripted generic types (including `Callable`, `Collection`, `Sequence`, `Mapping`, and `Union`), inspecting runtime type origins to validate values without raising type errors on subscripted generics.

- An *inner transition* executes the core operation and yields its return value to the outer transition. In an interface state machine, the transition method delegates to an inner transition method (`inner_<method>`) that computes and returns the fake return value. In an implementation pseudo state machine, the inner transition method is overridden to evaluate additional pre-assertions on the target, invoke the concrete implementation under test, evaluate additional post-assertions on target state, and return the real return value to the outer transition (ignoring any fake return value returned by calling the super inner transition).

- A *post-call slice* updates model state and verifies postconditions, state differentials, and contract invariants via native single-argument `assert condition` statements. Assertions evaluate uniformly in both verification mode (against the real target) and Fake mode (against the synthesized fake). Impossible defensive branches are marked with `unreachable(reason)` and excluded from test coverage.

- A *test-only query* (`@test_only`) declares an observability accessor on an interface specification for black-box state verification, forbidden from production library calls by linters.

Argument domains support scalar categoricals, constant values via just, discrete ranges via range, set membership via in_set, set exclusion via not_in, unconstrained values via any, and domain specializations.

A *state machine* declares the complete behavioral contract of an interface through state transitions and system invariants. An *implementation pseudo state machine* inherits from an interface state machine, defining zero state dataclasses of its own, omitting argument requirements (`require_arg`), and overriding inner transition methods to execute target calls and evaluate target-specific pre- and post-assertions without onion dispatch wrappers or magic return-value interception. When an implementation pseudo state machine transition executes, domain constraints, generation strategies, precondition assertions, and reference model state updates are inherited from the parent interface state machine, invoking the overridden inner transition directly through standard method polymorphism. A state machine drives implementation logic under test through a *checked adapter* (`sm.bind(target)`) that executes transitions around target invocations, or provides a synthesized in-memory *fake adapter* backed by the shared reference model. For fixed scenario testing of contract violations, the checked adapter exposes contract violation testing (`adapter.violating(exc_type, match="")` and context manager `with adapter.violating(...)`). In violating mode, antecedent preconditions (`require`, `require_arg`) are disabled so the real implementation under test is invoked and its error-raising branch is executed and measured by coverage tools; the adapter asserts that the target invocation raises the contracted exception, verifying and capturing it so the test passes. Because a contract violation places the component in an undefined state, the checked adapter marks the instance terminal upon violation; subsequent operational transitions on that adapter raise a specification error, enforcing that contract violation testing is strictly the terminal transition of an instance. Interface components compile Hypothesis property fuzz tests (`compile_hypothesis_test_case`) to verify synthesized fakes directly against their own state machine contracts. A *trace step* records the operation name, arguments, and outcome of an executed transition within a state machine run.

A *runner configuration* specifies test execution parameters including target paths, fuzzing iterations, statement coverage thresholds, execution timeout durations, and active step diagnostic reporting. A *run result* reports execution metrics, including passed test counts, failure counts, statement coverage percentages, and synthesized counterexamples.
