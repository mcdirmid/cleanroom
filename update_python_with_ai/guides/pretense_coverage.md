# Guide: Pretense Coverage Arbiter

## Summary

The verification targets are the library implementation (`lib/<name>.py` or `lib/<name>_impl.py`) and the Pretense test suite (`pretense/<name>_pretense.py` or `pretense/<name>_impl_pretense.py`) for the specified unit. Interface specification modules (`lib/<name>.py` defining protocols, dataclasses, and enums in two-file units) are excluded from pretense coverage auditing. In a multi-node session, multiple targets are evaluated together; each target is evaluated and submitted independently via `submit(target="<target_file>")` once 100% statement coverage is achieved, which stamps `PRETENSE_COVERAGE_AUDIT: <timestamp>` into the in-band metadata blocks of `lib/<name>.py` (or `lib/<name>_impl.py`) and `pretense/<name>_pretense.py` (or `pretense/<name>_impl_pretense.py`) without modifying their last changed timestamps. All code files (both lib and pretense files) are strictly read-only for pretense coverage; calling file editing tools on code files is prohibited, pretense coverage never edits `.py` files directly, and pretense coverage delivers defect attribution exclusively via the `blame` tool (specifying the blamed file `lib/<name>.py`, `lib/<name>_impl.py`, `pretense/<name>_pretense.py`, or `pretense/<name>_impl_pretense.py`). When coverage deficits involve both roles (such as uncovered requirements in pretense tests and unreachable code in the library), the arbiter attributes blame to each culprit file (`pretense/<name>_pretense.py` and `lib/<name>.py` or their `_impl` counterparts) within the current round. Deficit diagnosis is concise (under 200 words); the arbiter inspects uncovered lines in the library implementation with line numbers enabled, translates uncovered code into missing specification requirements, and delivers targeted blame. The search tool is never installed.

Blame feedback is strictly a single paragraph containing no newline characters; line breaks, multi-line formatting, and bulleted lists in blame explanations are prohibited. Feedback must be provided in terms of how the file being blamed is not compliant with the common source of truth specification. Line numbers can be mentioned only if they reference the file being blamed; exposing line numbers, code details, or internal variables of other files is strictly prohibited. Blame feedback delivered to the pretense module is strictly non-prescriptive, identifying only what specification requirements and behavioral aspects lack test coverage; it is framed strictly as missing unit test cases or transition assertions verifying specification postconditions, invariants, or error branches from low-level specifications, and never phrases deficits as defects or missing behaviors in library classes (e.g. stating that a class or method 'does not' perform an action), never prescribes test scenario designs, mock setups, or code snippets, and never mentions library file names, file paths, line numbers, or internal variable names. Blame feedback delivered to the library module is strictly restricted to reporting that code is unreachable under the specification, instructing the library to either restructure the code to eliminate the dead code or annotate it with `# pragma: no cover (assumption: <reason>)` for impossible branches or caller assumptions guaranteed by the contract; diagnosing functional bugs or prescribing functional logic changes to library code is prohibited. When a coverage deficit is attributable to missing unit tests in the pretense suite, blaming `pretense/<name>_pretense.py` fully resolves the assigned target; delivering blame, courtesy notices, or informational updates to `lib/<name>.py` when the library implementation contains no unreachable code or dead code is strictly prohibited. When 100% statement coverage is achieved and verified, calling `blame` is prohibited, and the target concludes via the `submit` tool, stamping `PRETENSE_COVERAGE_AUDIT` across both verified target files. When coverage cannot be achieved without violating the contract and the code cannot be restructured or annotated with a pragma, the run fails via the `fail` tool instead.

> META: "The pretense coverage arbiter attributes uncovered lines to missing specification requirements or caller assumptions without modifying code files directly."

## Deficit diagnosis and blame feedback

- [ ] In multi-node sessions, each target is evaluated independently for its corresponding module, and submitted individually via `submit(target="<target_file>")`
- [ ] All code files are strictly read-only: the agent never modifies `.py` files directly
- [ ] Uncovered statements are inspected by reading the library implementation file with line numbers enabled
- [ ] Coverage evaluation presents all uncovered statement spans per cycle without throttling, enabling the arbiter to diagnose all active deficits together
- [ ] Blame feedback delivered to the pretense module is strictly non-prescriptive: it identifies only which specification requirements and behavioral aspects lack test coverage, leaving test design, transition assertions, and state machine structure entirely to the pretense module
- [ ] Blame feedback delivered to the pretense module is framed strictly as missing test cases or transitions asserting specification postconditions, invariants, or error branches, and never phrases deficits as defects or missing behaviors in library classes
- [ ] Blame feedback delivered to the pretense module never prescribes test implementations, mock configurations, fixture designs, variable values, or assertion code snippets
- [ ] Anti-contamination: blame feedback must be provided in terms of how the file being blamed is not compliant with the common source of truth specification (the low-level specification and imported interface/boundary contracts in module_deps); line numbers may be mentioned only if they reference the file being blamed; mentioning line numbers, file names, file paths, internal variables, helper methods, or private execution branches of other files is strictly prohibited
- [ ] Blame feedback delivered to the pretense module never instructs tests to assert unmandated behaviors, internal implementation artifacts, or fabricated requirements observed in uncovered library code
- [ ] Blame feedback delivered to the pretense module never instructs tests to access private attributes, manipulate internal collaborator state, or invoke uncontracted methods to force execution through defensive branches; unreachable defensive branches are attributed to the library module for pragma annotation or dead code elimination
- [ ] Strictly public contract boundary: blaming tests for failing to cover internal helper functions, private methods (names starting with '_'), or implementation-specific subroutines is strictly prohibited; coverage deficits must be articulated purely in terms of public API entry points defined in the low-level specification (`low/*.pyi`)
- [ ] Uncontracted non-concerns and defensive branches: when library code implements defensive checks or fallback branches for uncontracted non-concerns (conditions not specified in the low-level contract closure), instructing tests to test those branches is strictly prohibited; unreachable defensive branches must be attributed to the library module to prune as dead code or annotate with `# pragma: no cover (assumption: <reason>)`
- [ ] Repeating identical blame feedback across cycles for an unyielding deficit is prohibited: when previous feedback fails to achieve coverage, the arbiter deepens analysis of the specification contract to formulate distinct requirement aspects or evaluates whether the code is unreachable
- [ ] In multi-target sessions, the `blame` tool specifies the bound target file receiving blame (`lib/<name>.py` or `pretense/<name>_pretense.py`)
- [ ] Multi-role defect attribution: when coverage deficits span both the pretense module and the library module, blame is attributed to each culprit file (`pretense/<name>_pretense.py` and `lib/<name>.py`) within the current round
- [ ] Test deficit target resolution: when a coverage deficit is attributable to missing tests in `pretense/<name>_pretense.py`, delivering blame to `pretense/<name>_pretense.py` fully resolves the assigned target; delivering courtesy blame or status feedback to `lib/<name>.py` when the library implementation contains no unreachable code is strictly prohibited
- [ ] Blame feedback paragraph format: the blame explanation string is strictly a single paragraph containing no newline characters; multi-line formatting, line breaks, and bulleted lists in blame explanations are prohibited
- [ ] Blame feedback delivered to the library module is strictly restricted to reporting that specific code is unreachable under the specification closure: the feedback instructs the library module only to either restructure the code to eliminate the unreachable code or annotate it with `# pragma: no cover (assumption: <reason>)` when the code represents an impossible branch or caller assumption guaranteed by the contract
- [ ] Blame feedback delivered to the library module never diagnoses functional bugs, contract deviations, or algorithmic logic errors, and never prescribes functional code fixes; functional defect arbitration belongs exclusively to Pretense QA
- [ ] When coverage cannot be achieved without violating the specification contract and the code cannot be eliminated by restructuring or justified by an assumption pragma, the session concludes via the `fail` tool
- [ ] When 100% statement coverage is achieved and verified, calling the `blame` tool is prohibited, and the target concludes via the `submit` tool

## Lint checks

- [ ] Applies to implementation modules with a corresponding pretense test suite (excluding pure interface definitions)
- [ ] Pretense test files pass pretense linter checks, containing no private member access or reflection on target classes or instances
- [ ] The verified target files (`lib/<name>.py` or `lib/<name>_impl.py`, and `pretense/<name>_pretense.py` or `pretense/<name>_impl_pretense.py`) contain valid `PRETENSE_COVERAGE_AUDIT` metadata tags upon successful completion
