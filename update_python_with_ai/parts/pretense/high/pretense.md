# pretense interface component

## Purpose

The pretense interface component defines the declarative state machine abstractions, sentinels, collection models, transition specifications, fake adapters, and verification engine contracts for stateful software testing in Cleanroom.

Example-based testing and AST statement coverage frequently miss critical state desynchronizations, boundary regressions, and omitted invariant logic in neural-generated code. By defining stateful systems as executable state transition models rather than static unit test sequences, this component enables automated property-based exploration, invariant checking across arbitrary operation orderings, and automatic fake synthesis. Centralizing these state abstractions prevents fragmentation across test harnesses and ensures that specification contracts remain mathematically verifiable.

**Out of scope:** Subprocess invocation, filesystem scanning, and shell argument parsing; these are handled by other components.

## Types and Behavior

A system's *pretense engine* coordinates state machine compilation, test suite execution, and fake generation.

A *pretense sentinel* distinguishes unprovided inputs and specific runtime states from standard program values. The sentinel *not bound* indicates that a parameter was omitted by a caller. An *execution outcome* encapsulates the result of evaluating an operation against an implementation under test. A *value outcome* wraps a successful return value. A *raised outcome* wraps an expected or intercepted exception instance. A *specification error* indicates that a state machine contract, transition invariant, or antecedent predicate was violated.

A *draw context* provides a dynamically bound generator for sampling values during property-based test exploration. A *pretense collection* provides an observable state container that tracks mutations and verifies invariants. A *pretense dictionary* provides an observable key-value mapping with existence assertions and weighted key selection. A *pretense set* provides an observable unique item container with element sampling and existence assertions.

A *state transition* defines a single atomic operation step within a state machine. Each state transition specifies a *requires* condition that must hold before the operation executes, an *argument binder* that generates or recognizes operation arguments, an expected return outcome or contracted exception, an *ensures* postcondition verified against the concrete singleton under test during real test execution, and an *update* condition that applies reference model state mutations. An *argument domain* unifies generative sampling with analytical validation for an operation parameter. A domain produces randomized values conforming to its specification during property fuzzing and validates whether arbitrary candidate values belong to its domain during adapter dispatch. Argument domains support scalar categoricals, discrete ranges, lexical patterns, structural data types, dependent parameter domains whose boundaries derive dynamically from preceding arguments, and constructive perturbations that derive candidate values from anchor values via targeted near-boundary mutations. An argument binder binds transition arguments exclusively from explicit domains, native collections, ranges, patterns, data types, dependent domain functions, and keyword domain mappings. An unresolved domain placeholder enforces explicit domain definition by failing at runtime if left unspecialized. An argument binder generates operation arguments from direct values, callables, domains, or property-based search strategies treated directly as values, automatically drawing randomized instances from active draw contexts during property fuzzing while drawing default examples when evaluated outside fuzzing contexts. A *transition context* provides methods for specifying requires preconditions, argument binders, expected returns, contracted exceptions, ensures postconditions, and model updates for a single transition method. A transition context provides a *check helper* for evaluating requirements without exception overhead and evaluating postconditions against immediate and collaborating singletons under test during real test runs while omitting ensures verification during fake adapter dispatch. A transition context strictly enforces mutual exclusivity between expected returns and contracted exceptions: declaring both on the same transition context raises an invalid transition definition error. When synthesizing fake exceptions from contracted exception types, the transition context safely instantiates exception classes that declare mandatory positional parameters. A *transition decorator* registers a transition method against a target singleton class operation.

A *state machine* declares the complete behavioral contract of an interface or implementation through a collection of state transitions and system invariants. A state machine stores singletons under test as direct references in its state representation to drive implementation logic under test, or provides synthesized in-memory fake adapters backed by the shared reference model. A *fake adapter* acts as a dynamic test double conforming to an interface protocol, delegating method invocations directly to matching state transitions and verifying preconditions. A *trace step* records the operation name, arguments, and outcome of an executed transition within a state machine run.

A *runner configuration* specifies test execution parameters including target paths, fuzzing iterations, statement coverage thresholds, execution timeout durations, and active step diagnostic reporting. A *run result* reports execution metrics, including passed test counts, failure counts, statement coverage percentages, and synthesized counterexamples.
