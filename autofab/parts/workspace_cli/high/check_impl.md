# check_impl implementation component

imports: session, submit, pending, role_registry, sync, work
implements: check

## Purpose

The check_impl implementation component realizes work queue discovery, actionable task formatting, template regeneration, and file verification runners for Autofab role workspaces.

Guiding subagents in role workspaces requires pulling changes from the canonical main workspace, evaluating dirty tasks, enforcing pending buffer resolution, and executing verification rules with starter template regeneration when targets are missing. The check_impl implementation component realizes these developer loop operations within the agent session lifecycle tier.

**Out of scope:** The check_impl implementation component does not submit changes, attribute blame critiques, evaluate test coverage, or provision workspaces; these are handled by other components.

**Delegated:** Session tier scoping is delegated to agent_session; workspace role definitions and resolution are delegated to role_registry; queue evaluation is delegated to work; pending work buffer tracking is delegated to pending; pulling changes is delegated to sync; submit target resolution is delegated to submit.

## Types and Behavior

The workspace checker realization implements work discovery and verification workflows for Autofab role workspaces.

The checker:

- Pulls inbound changes from the canonical main workspace during work execution, evaluates whether prior dirty targets remain pending in the role workspace via the pending manager (bypassing destructive inbound pull when executing in a fused role workspace or auditor role workspace), relisting assigned pending targets directly as ready work items when dirty work is already set rather than emitting an error, verifies when `gemini-argon` (or `gemini-4-argon`) is configured on the `antigravity` harness that the active Antigravity subagent conversation is actually executing on `gemini-argon` (aborting with an explicit error instructing the user to manually switch their Antigravity model to "Gemini Argon" before requesting the run again when a non-argon model is detected), resolves batch size and feedback throttling limits from configuration or arguments, evaluates ready and blocked items from the work manager, and for auditor roles (roles declaring an audit tag or lacking source patterns), aggressively executes verification checks on each discovered ready dirty target before presenting work: when verification checks pass on a target, automatically submits the target with audit attestation via the submission coordinator, logs the submission, and excludes it from presented work items; when verification checks fail on a target, retains the failing target in the ready work queue without outputting failure diagnostics or triage summaries during work acquisition (leaving failure diagnostics to be surfaced when the worker executes `check_files` directly); and when all ready dirty targets pass and are auto-submitted (or when no ready targets are available), clears the pending work buffer, records that no pending work remains, formats a prominent round conclusion directive instructing the worker that all work assigned to their role in this round is resolved, and directing the worker that they must conclude their round immediately with zero further tool calls; while for authoring roles, records the bounded batch of pending targets via the pending manager, presents exclusively the assigned ready targets without extraneous remaining or blocked queue details, throttling unacted feedback reasons exceeding maximum character limits, resolves the companion guide declared for the active role from the role registry, resolving its path relative to the role workspace root (`guides/<basename>`), and formats actionable next steps including specification contracts, reasons and feedback driving the work, and the workspace-relative companion guide to follow for presented and pending targets, with tailored resolution workflows for author, auditor, and fused roles.

- Resolves the active role, target files, and active model failure limits during check files execution, extracting max_failures from the active model configuration (defaulting to 5 for local engines and 100 for non-local models when unspecified) and propagating failure limits to test execution runners, enforces that verification cannot be executed when the role workspace has zero pending work assigned and zero ready items in the active work queue when no target is specified (reporting failure and directing the worker to call get_work first or conclude the round, while reporting no targets to check when neither target nor pending work is present), verifies that any specified target file belongs to the active pending work buffer, ready work queue, or is owned by the active role before executing checks (reporting failure when an unassigned target not owned by the active role is requested), pulls inbound changes and refreshes system files from the canonical main workspace before executing checks, verifies that package `__init__.py` files and other read-only files outside the role's writeable file patterns have not been modified, reporting verification failure and reverting unauthorized modifications when detected, regenerates a missing target file from its starter template for roles that declare source patterns and upstream dependencies before verification, executes the corresponding static linting, type-checking, or test rules assembling the verification execution environment bounded strictly to the active role workspace directory and its constituent package directories, isolating verification from the canonical repository root in PYTHONPATH and sys.path, configuring UV_CACHE_DIR to a sandbox-accessible directory under temporary directories (e.g. /tmp/uv_cache) to prevent external cache write denials under workspace-write sandbox boundaries, enforcing an execution timeout on verification commands to prevent blocked or hung sub-processes from stalling the workspace developer loop and reporting verification failure with explicit diagnostic messaging that the timeout indicates a code defect (such as an infinite loop, deadlock, or live-lock) rather than an infrastructure failure when execution expires, records verification execution records and file hashes in the workspace to gate subsequent submissions, blame, or failure operations on modified files, records an in-workspace git milestone checkpoint commit when verification checks succeed with zero errors for authoring roles with writable targets to preserve working code states (omitting milestone commits for auditor roles with zero writable targets), surfaces warning notifications and unacted feedback items when targets carrying unaddressed feedback pass static verification checks to alert agents that static checks do not verify runtime behavior or test assertions, sanitizes verification process output by stripping redundant embedded arbiter reminders before display, formats clean diagnostic outcomes, surfaces a structured triage diagnostic summary when verification fails for auditor roles extracting the author's latest change commit header, primary failure diagnostics, and candidate culprit files to immediately guide blame attribution without ad-hoc exploratory script authoring, formats blame routing instructions directing the arbiter to inspect the specification and source code across candidate feedback targets (library, test, and pretense) to determine which file to blame for each defect, surfaces prominent specification grounding reminders directing the agent to formulate blame feedback strictly in terms of how the blamed file is not compliant with the common source of truth specification, permitting line numbers only within the blamed file while strictly forbidding exposing details of other files, and instructing the agent when an uncovered line persists across rounds or after test updates to examine the library implementation closely to determine whether the line is structurally or logically unreachable, and returns the verification exit status.
