# DSH Part (`update_with_ai/parts/dsh`)

## Purpose

The **dsh** part provides the platform integration adapter between Cleanroom and the DeepSeek Harness (DSH) environment, supporting both the headless DSH command-line interface and the DeepSeek Harness Desktop application.

Running multi-agent Cleanroom pipelines under DeepSeek Harness requires spawning autonomous agent subprocesses in confined role workspaces, enforcing non-interactive unattended permissions, harvesting token metrics from stdout event streams or compressed session storage, and communicating session identity to the local Desktop GUI over an RPC bridge. The dsh part encapsulates all DeepSeek Harness process dispatching, telemetry extraction, Cordis configuration patching, and desktop synchronization.

## Key Components & Specifications

According to the high-level specifications in [`update_with_ai/parts/dsh/high/`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/dsh/high):

- [`dsh_harness.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/dsh/high/dsh_harness.md) & [`dsh_harness_impl.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/dsh/high/dsh_harness_impl.md): Implements the Cleanroom harness adapter for DeepSeek Harness. It dispatches role turns to `dsh` CLI subprocesses within provisioned role workspaces, tracks process lifecycles without mandatory timeouts (terminating only when explicit limits are set), monitors workspace pending work and blame buffers, and synthesizes role turn results.
- [`dsh_telemetry.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/dsh/high/dsh_telemetry.md) & [`dsh_telemetry_impl.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/dsh/high/dsh_telemetry_impl.md): Extracts prompt, cached, and completion token metrics from DSH stdout JSON event streams or falls back to regex matching over process logs. When stream events are truncated, it decompresses local session archives (`session.v4.jsonl.zstd`) using zstd, calculates financial expenditures via multi-model rate cards, synchronizes session records with the Chromium-backed Desktop storage (`workspace.json` and session projcache), and notifies running Desktop applications via local cookie-authenticated RPC calls.
- [`dsh_workspace.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/dsh/high/dsh_workspace.md) & [`dsh_workspace_impl.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/dsh/high/dsh_workspace_impl.md): Configures and confines isolated role workspaces for DSH. It tailors role agent documentation (`AGENTS.md`) with explicit isolation boundaries, tripwires, and command execution restrictions (confining shell execution strictly to the prescribed workspace binaries: `get-work`, `check-files`, `submit`, `blame`, `status`). It also generates a Cordis overlay patch (`.cleanroom/dsh_patch.yml`) configuring danger-full-access permissions, `approval_policy: never`, disabled plugins, and declarative model profile routing for unattended execution.
- [`dsh_ext.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/dsh/high/dsh_ext.md): Defines external protocol schemas for DSH: CLI invocation flags, JSON stream event schemas, Cordis patch YAML schemas, Desktop storage directory layouts, and RPC bridge payload formats.
- [`dsh_asm.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/dsh/high/dsh_asm.md): Assembles the DSH harness adapter, telemetry parser, and workspace configurer into an operational service registered with the harness registry.

## How It Is Used by Other Parts

- **`subagent`**: Installs the DSH harness adapter into `subagent_harness`'s central `HarnessRegistry`. When the orchestrator executes with `--harness dsh`, the subagent coordinator resolves this adapter to dispatch role turns into DSH workspaces and harvest outcome telemetry.
- **`workspace`**: Collaborates with `dsh_workspace` during role workspace provisioning so that newly created role workspaces receive DSH-specific agent instructions (`AGENTS.md`) and Cordis overlay patches (`.cleanroom/dsh_patch.yml`) before subagents are launched.
- **`tools`**: The agent instructions generated by `dsh_workspace` direct DSH agents to interact with the repository strictly through the CLI binaries provided by the `tools` part (`bin/get-work`, `bin/check-files`, `bin/submit`, `bin/blame`, `bin/status`).
- **Top-Level CLI & Support (`cleanroom_role_tool`)**: Used when running `cleanroom orchestrate ... --harness dsh` to drive autonomous pairs in DeepSeek Harness environments.
