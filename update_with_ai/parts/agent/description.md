# Agent Part (`update_with_ai/parts/agent`)

## Purpose

The **agent** part establishes the foundational session abstractions, operational policies, virtualized file addressing, and target-level execution configurations governing autonomous AI agent interactions in Cleanroom.

Rather than exposing physical host paths and ambient machine environments directly to language model agents—which causes hallucinated paths, cross-environment drift, and context pollution—the agent part creates a secure, virtualized execution boundary. It defines the lifecycle scope for individual agent sessions, restricts file interactions through virtual file aliases with explicit read/write permission tiers, parses and extracts model configuration parameters, and models task prompts and node definitions for dependency-directed workflows.

## Key Components & Specifications

According to the high-level specifications in [`update_with_ai/parts/agent/high/`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high):

- [`agent_session.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/agent_session.md): Defines the canonical lifecycle tier identifying agent session boundaries beneath the system-wide application environment. It ensures that ephemeral conversation state, session configurations, and tool allocations do not leak across distinct agent runs.
- [`agent_config.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/agent_config.md): Formalizes system-level operational policies and execution limits for agent sessions, including conversation turn limits, trailing character limits for superseded arguments (`supersede arg keep`), follow-up tool call injection, progressive guide delivery (`step mode`), startup file inspection, and delta-based edit reporting.
- [`agent_file_alias.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/agent_file_alias.md): Decouples agent session file operations from physical filesystem paths. It provides the `FileAlias` abstraction distinguishing *bound files* (mapped to workspace files with an owning node, categorized as *read-only* or *read-write*) from *unbound files*. It provides the `AliasManager` which resolves relative string paths to file aliases and sanitizes agent-visible text by masking host filesystem paths.
- [`agent_node_config.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/agent_node_config.md): Unifies node-level execution configurations for an active session. It models `RoleConfig` (the active role, sequence of nodes being cleaned, and execution version counter) and `SessionConfig` (resolved read-only and read-write files, step-by-step guides, starter templates and template parameters, verification checks, blame targets, and incoming defect feedback).
- [`agent_storage.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/agent_storage.md): Extends DAG storage with target manifest metadata. It preserves target definitions, task prompts, and dependency relationships, and evaluates node dirtiness dynamically by comparing in-band source file metadata against dependency change timestamps.
- [`model_config_ext.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/model_config_ext.md): Defines the external JSON dictionary schema for model configurations emitted by build rules, specifying target labels, model identifiers, API endpoint URLs, credential environment variable names, timeouts, turn limits, sampling temperatures, token bounds, and feature toggles.

## How It Is Used by Other Parts

The `agent` part is a central domain contract consumed across the entire Cleanroom ecosystem:

- **`control`**: Uses [`agent_node_config.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/agent_node_config.md), [`agent_file_alias.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/agent_file_alias.md), and [`agent_storage.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/agent_storage.md) to set active session roles, discover ready dirty tasks, synthesize task prompts with user-facing aliases, evaluate verification checks, and attribute defects back to culprit upstream nodes.
- **`sandbox`**: Relies on [`agent_file_alias.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/agent_file_alias.md) and [`agent_node_config.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/agent_node_config.md) to enforce read-only vs. read-write permissions during file reads and edits, deliver progressive guides, evaluate verification checks in `check_files`, and validate blame targets during `submit`, `fail`, or `blame`.
- **`workspace`**: Uses [`agent_file_alias.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/agent_file_alias.md) and [`agent_node_config.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/agent_node_config.md) to map declared bound files, scaffold initial project trees, populate starter templates, and synchronize files between isolated role workspaces and the canonical workspace.
- **`subagent`**: Uses [`agent_session.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/agent_session.md), [`agent_node_config.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/agent_node_config.md), and [`agent_storage.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/agent_storage.md) to configure session scopes and task instructions when dispatching roles to autonomous subagents.
- **`antigravity` & `dsh`**: Use [`agent_session.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/agent/high/agent_session.md) and session config types to bind execution turns to isolated role environments in Google Antigravity and DeepSeek Harness.
