# Sandbox Part (`update_with_ai/parts/sandbox`)

## Purpose

The **sandbox** part implements the sandboxed agent tool provider and runtime environment for Cleanroom. It supplies the concrete tools that language models use to inspect workspaces, modify code, receive progressive step guidance, run verification checks, and resolve tasks through submission or blame.

Allowing language model agents unconstrained access to host commands or raw operating system files invites accidental file overwrites, security violations, and context drift. The sandbox part exposes a strictly governed tool interface where file reads and edits are restricted to declared file aliases and permissions, verification commands are run through noise-scrubbing runners, progressive step instructions are paced across turn boundaries, and task completions require verified change documentation.

## Key Components & Specifications

According to the high-level specifications in [`update_with_ai/parts/sandbox/high/`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/sandbox/high):

- [`tool_provider.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/sandbox/high/tool_provider.md) & [`tool_provider_impl.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/sandbox/high/tool_provider_impl.md): Defines the core tool management architecture. It maintains installed tools, generates deterministic JSON function schemas for language model prompts, dispatches invocations with automatic parameter coercion (e.g. converting raw string paths into validated `FileAlias` instances), formats tool responses with active notes and reminders, and supports follow-up tool call injection.
- [`file_reader.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/sandbox/high/file_reader.md) & [`file_reader_impl.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/sandbox/high/file_reader_impl.md): Provides safe file inspection tools (`read_file`, `list_directory`). It ensures agents only read files through valid file aliases, prevents reading outside session boundaries, and sanitizes output by masking physical host paths with relative alias names.
- [`file_editor.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/sandbox/high/file_editor.md) & [`file_editor_impl.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/sandbox/high/file_editor_impl.md): Provides file editing tools (`replace_file_content`, `write_to_file`). It enforces write permission gating (only files configured as *read-write* may be modified), applies contiguous block replacements safely, tracks modified files, and optionally emits compact diffs rather than full file contents when delta output policy is active.
- [`guide_delivery.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/sandbox/high/guide_delivery.md) & [`guide_delivery_impl.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/sandbox/high/guide_delivery_impl.md): Manages progressive, step-by-step instructional delivery when `step_mode` is enabled. It exposes the `advance` tool, guides agents through sequential step sections, and provides tailored recovery guidance upon verification failures.
- [`run_control.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/sandbox/high/run_control.md) & [`run_control_impl.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/sandbox/high/run_control_impl.md): Implements the `check_files` verification tool. It evaluates configured verification checks across active nodes, scrubs compiler diagnostic noise, caches outcomes by file hash, reminds the agent when files have not changed since the last check, and gates progression.
- [`submission.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/sandbox/high/submission.md) & [`submission_impl.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/sandbox/high/submission_impl.md): Implements outcome resolution tools (`submit`, `fail`, `blame`). It requires passing verification before submission, enforces change summary documentation for modified files, validates blamed targets against configured blame dependencies, and produces non-terminating responses if additional active batch nodes remain.
- [`template_format.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/sandbox/high/template_format.md) & [`template_format_impl.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/sandbox/high/template_format_impl.md): Evaluates text templates by interpolating session configuration parameters and variables into prompts and guidance messages.
- [`sandbox_asm.md`](file:///Users/seanmcdirmid/projects/cleanroom/update_with_ai/parts/sandbox/high/sandbox_asm.md): Assembles the file readers, editors, guide delivery, run controllers, submission tools, and template formatters into an operational sandbox tool provider.

## How It Is Used by Other Parts

- **`loop`**: The `driver` and `guard` invoke sandbox tools during agent turns, checking tool arguments against repetition thresholds and passing execution results back to conversation history.
- **`openai`**: `driver_impl` retrieves tool definitions from `tool_provider` to build the model completion payload and dispatches incoming tool calls back to the sandbox provider.
- **`control`**: The sandbox submission and verification tools directly invoke `verification`, `submit`, and `attribution` via the session coordinator.
- **`systems`**: Aggregated into `openai_loop_asm` and `cleanroom_asm`.
