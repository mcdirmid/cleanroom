# Guide: Pretense QA Arbiter

## Summary

Verification targets are the library implementation (`lib/<name>.py`) and companion Pretense test suites (`pretense/<name>_pretense.py` or `pretense/<name>_impl_pretense.py`), evaluated alongside imported interface state machines (`pretense/<iface>_pretense.py`). Running verification executes the Pretense test suite via `uv run pretense <target_file>` to produce fresh execution diagnostics. While `lib/<name>.py` is the target presented to `bin/check_files`, verification actually executes companion pretense state machines; the arbiter never assumes `lib/<name>.py` is the culprit simply because it is the check target. Before attributing blame to `lib/<name>.py`, the arbiter inspects `low/<name>.pyi` to determine whether the failing assertion demands uncontracted behavior; if the assertion overspecifies or contracts behavior absent from `low/<name>.pyi`, the blame belongs to the test oracle (`pretense/<name>_impl_pretense.py`), not `lib/<name>.py`. All code files are strictly read-only for Pretense QA; direct file editing or writing debug scripts is prohibited. Clean targets passing verification are automatically submitted by `bin/get_work`, stamping `PRETENSE_QA_AUDIT` into in-band metadata. When verification fails, the arbiter stages blame one item at a time via `blame(target="<culprit_file>", critique="<critique>")` with exactly two arguments: the culprit file and an actionable single-paragraph critique containing zero newline characters. When Hypothesis reports an ExceptionGroup or multiple failure traces, the arbiter audits and stages blame strictly against the primary (shortest) failure trace immediately without inspecting secondary failure traces. Once all blame is staged, the arbiter commits blame and concludes the target via `submit(target="<target>")`. Manual `submit` in auditor roles strictly requires preceding staged blame. The search tool is never installed.

The component's low-level specification (`low/<name>.pyi`) and imported contracts (`low/<iface>.pyi`, `low/<dep>.pyi`) are the exclusive sources of truth. Pretense QA audits active failures strictly against these specifications. Any failure—including test assertion failures, unexpected exceptions, unhandled errors, or fuzzer crashes—indicates a defect in either the library implementation, the pretense tests, the component's interface state machine, or an imported dependency's interface state machine. Blame `lib/<name>.py` only when the library implementation contains the defect (such as violating contracted postconditions or invariants, misusing collaborators or fakes, or raising unexpected errors on valid inputs). Blame `pretense/<name>_impl_pretense.py` when the implementation test contains the defect (such as improper fixtures, overspecified oracles, invalid test scenarios, failure to initialize or register required collaborator singletons in the test lifecycle registry causing `LifecycleResolutionError`, or incorrect collaborator seeding). Blame the component's interface state machine (`pretense/<iface>_pretense.py`) when it models its interface incorrectly (such as inaccurate state transitions, wrong attribute modeling, or missing `require(...)` gates on modeled state). Blame an imported dependency's interface state machine (`pretense/<dep>_pretense.py`) when the dependency interface is modeled incorrectly or the fake synthesized for the import produces incorrect return values, invalid state transitions, or violates `low/<dep>.pyi` contracts. Blaming `lib/<name>.py` for companion pretense state machine bugs (wrong attribute modeling, missing preconditions) or critiquing how a library author's `# CHANGE:` failed to resolve pretense issues is strictly prohibited because library authors do not own and cannot edit pretense state machines. In feedback to library modules, referencing tests, test line numbers, or test frameworks is prohibited. In feedback to pretense modules, referencing private library implementation details, private variables, or internal helper methods is prohibited.

> META: "The Pretense QA arbiter diagnoses active Pretense test failures against low-level interface contracts without auditing passing tests or modifying code directly."

## Defect diagnosis and blame feedback

- [ ] In multi-node sessions, each target module is evaluated independently and submitted individually via the submission tool
- [ ] Active test failures and execution status are determined exclusively from fresh test verification output at the start of the round; attributing blame on stale output is prohibited
- [ ] Evaluating requirement completeness or statement coverage belongs exclusively to the Pretense Coverage Arbiter; coverage omissions are not audited or blamed by QA
- [ ] Clean targets passing verification are automatically submitted by `bin/get_work`; manual `submit` without preceding staged blame is prohibited
- [ ] Low-level specifications (`low/<name>.pyi`, `low/<name>_impl.pyi`) and imported interface contracts are the exclusive sources of truth for behavior, postconditions, and exceptions
- [ ] Mandatory blame execution on failure: concluding the round with conversational text without staging `blame` and committing via `submit` is prohibited
- [ ] Delivering defect attribution stages blame one piece at a time via `blame` with exactly two arguments: the culprit file (`lib/<name>.py`, `pretense/<name>_impl_pretense.py`, `pretense/<iface>_pretense.py`, or dependency `pretense/<dep>_pretense.py`) and the actionable critique message, followed by `submit(target="<target>")` to commit blame

<!-- if experiment:structured_blame -->

- [ ] Structured blame tuple format (mandatory under structured_blame): blame critique MUST use the structured tuple format:
  `bin/blame <culprit_file> "[slug:<spec.slug>] Violation: <noun phrase> Facet: <noun phrase> Lines: <range> Witness: <key_value_pairs>"`
  or via taxonomy tag format:
  `bin/blame <culprit_file> "[slug:<spec.slug>] [viol:<prefix>.<name>] Facet: <noun phrase> Lines: <range> Witness: <key_value_pairs>"`
  or via CLI flags: `bin/blame <culprit_file> --slug <slug> --viol <viol> --facet "<noun phrase>" [--lines "<range>"] [--witness "<values>"]`
  - Specification slug: Must match a slug declared in `low/*.pyi`.
  - Violation section: Either a generalized non-prescriptive noun phrase (`Violation: <noun phrase>`, max 8 words, max 60 chars, no action verbs) or a taxonomy tag (`[viol:<prefix>.<name>]`). Canonical violation phrases for Pretense include `Violation: precondition error omission` (missing contracted error parameter on require/require_arg), `Violation: uncontracted negative assertion` (asserting raises on valid paths), `Violation: unhandled exception propagation` (uncaught error from call_target), and `Violation: postcondition divergence`.
  - Facet: Descriptive noun phrase of domain state/entity without verbs or commands (max 8 words, max 60 chars, e.g. `Facet: unregistered node identifier`, `Facet: numeric below string ranking`).
  - Lines (optional): Line number or range in culprit file (e.g. `Lines: 42` or `Lines: 42-50`, also accepts bracketed `[Lines: 42]`). Cannot reference foreign files or paths.
  - Witness: Literal key-value pairs (max 200 chars, e.g. `Witness: op=get_node, node='ghost', exp=NodeNotFoundError, obs=AssertionError`, also accepts bracketed `[Witness: ...]`). Conversational prose and prescriptive instructions are prohibited. Line numbers belong in `Lines:`, not Witness.

- [ ] Blame feedback is strictly diagnostic, specifying the problem location (line range and method/function name) and the violated specification requirement without prescribing code implementations or patch designs
- [ ] Public attribution purity: feedback delivered to library modules never references tests, test assertions, test file paths, or test line numbers, stating strictly how library code deviates from specification
- [ ] Encapsulation attribution purity: feedback delivered to pretense modules never references private library details, private variables, helper methods, or library line numbers, stating strictly how tests or state models deviate from specification
- [ ] Defect root-cause attribution: any failure—whether an assertion failure, raised exception, unhandled error, unreachable block tripwire, or stateful fuzzer crash—is diagnosed to identify the root cause against specification contracts without rigid exception-type decision paths
- [ ] Unreachable block two-stage triage: when a `with unreachable:` block or `unreachable()` raises `AssertionError` during a property fuzz test, blame `pretense/<name>_impl_pretense.py` to author a fixed scenario test that reaches the unreachable block; once a fixed scenario test is written and encounters the unreachable block, blame `lib/<name>.py` that the code is not unreachable under contracts, instructing the library author to remove `with unreachable:` and restore the implementation logic
- [ ] Target disparity & Oracle overspecification rule: while `lib/<name>.py` is the verification target presented to `check_files`, verification executes the companion pretense test suite; defaulting to blaming `lib/<name>.py` for test failures is strictly prohibited; when an assertion fails, verify that `low/<name>.pyi` explicitly contracts the asserted behavior before blaming `lib/<name>.py`; if the test asserts uncontracted behavior or overspecifies an oracle, blame `pretense/<name>_impl_pretense.py`
- [ ] Library defect attribution: blame `lib/<name>.py` when the library implementation deviates from specification, violates contracted postconditions or invariants, misuses library dependencies or fakes, or raises unexpected errors on valid execution
- [ ] Test defect attribution: blame `pretense/<name>_impl_pretense.py` when the failure originates in the implementation test suite, including invalid assertions, improper test fixture setup, erroneous transition overrides, or unseeded collaborator state
- [ ] Collaborator lifecycle error attribution: when a pretense test fails with `LifecycleResolutionError` for an external collaborator protocol (a singleton key not implemented by the target module), blame `pretense/<name>_impl_pretense.py` for failing to initialize or register the collaborator in `setUp`; blaming `lib/<name>.py` for unregistered foreign singletons is prohibited because library modules only register their own concrete singletons in `__initialize__`
- [ ] Interface model defect attribution: blame `pretense/<iface>_pretense.py` when the failure originates in the interface state machine, such as inaccurate state transitions, wrong attribute modeling (e.g. invalid state dataclass attributes), or missing `require(...)` gates on modeled state that permit generating invalid sequences; blaming `lib/<name>.py` for state machine modeling defects is prohibited
- [ ] Entity existence and missing precondition attribution: when a fuzzer or test crashes with an unhandled `*NotFoundError` or `*KeyError` during exploratory fuzzing on a valid transition, blame the interface state machine (`pretense/<iface>_pretense.py`) with `[viol:pre.missing_precondition] Facet: entity existence domain` to add `require(bool(self.state.<collection>))` and `require_arg(<param>, Domain.in_set(self.state.<collection>))` (optional `error=ExpectedError` documentation); blaming `lib/<name>.py` or attempting to catch `*Error` with `raises(...)` inside transitions is strictly prohibited
- [ ] Open parameter discrepancy attribution: when a divergence on initial state or property queries arises from an open parameter uncontracted by the public interface (such as initial capacity, buffer size, or thread limit) but contracted by the concrete realization (`low/<name>_impl.pyi`), blame `pretense/<name>_impl_pretense.py` to specialize the open parameter (by overriding the corresponding property hook or `make_initial_state()`); demanding that the interface state machine (`pretense/<iface>_pretense.py`) inline concrete realization constants is strictly prohibited
- [ ] Prohibition on blaming library changes for pretense defects: critiquing `lib/<name>.py` about how its `# CHANGE:` comment or patch failed to resolve companion pretense defects is strictly prohibited; the library author cannot modify pretense state machines
- [ ] Dependency interface and fake attribution: blame an imported dependency's interface state machine (`pretense/<dep>_pretense.py`) when the dependency interface is modeled incorrectly or the fake synthesized for the import produces incorrect return values, invalid state transitions, or violates `low/<dep>.pyi` contracts
- [ ] State mutations belong strictly to interface state machines: implementation pseudo-state machines (`*_impl_pretense.py`) are forbidden from mutating `self.state` (`PN_IMPL_NO_STATE_MUTATION`) and only invoke `call_target(...)`; state modeling defects belong to the interface state machine (`pretense/<iface>_pretense.py`)
- [ ] Operational postcondition exceptions vs contract violations: `with raises(ExpectedException):` is used exclusively for contracted operational postcondition exceptions (`*Exception`) resulting from seeded non-functional conditions; contract violations (`*Error`) are verified in fixed scenario tests via `checked.violating(ExpectedError).method(...)` (which self-asserts the exception and marks the adapter terminal), never via bare `raises(...)` inside transitions or wrapping in `assertRaises` (`assertRaises` is strictly prohibited in Pretense suites); in modules where all exceptions end in `*Error`, there must be ZERO `with raises(...)` blocks across the entire suite
- [ ] Prohibition on suggesting `raises()` for contract violations: claiming or blaming that contract violations (`*Error`) should be handled with `with raises(...)` is strictly prohibited; `*Error` conditions designate invalid inputs that the state machine must gate out via `require(...)` and `require_arg(<param>, Domain.in_set(...))` (optional `error=ExpectedError` documentation), and verified in scenario tests via `self.checked.violating(ExpectedError).<method>(...)`
- [ ] Implementation pseudo-state machine attribution: test failures inside overridden transitions of implementation pseudo-state machines or inside `Test<Impl>Real` are attributed strictly to `pretense/<name>_impl_pretense.py`, never to upstream interface state machines; direct access to `self.real` in test methods is strictly prohibited (tests must drive the SUT via `self.checked`)
- [ ] Counterexample reproduction: when Hypothesis reports a minimal failing counterexample sequence (`Failing test case: ...`), the blame explanation catalogs the exact sequence of failing method calls and parameters within the single-paragraph critique
- [ ] Primary failure prioritization: when Hypothesis reports an ExceptionGroup or multiple distinct failure traces, blame attribution is diagnosed and staged strictly against the primary (shortest) failure witness; reading, inspecting, or cataloging all failure clusters across an ExceptionGroup is prohibited
- [ ] Multi-role defect attribution: when failures span multiple roles, attribute blame to each culprit file separately within the round
- [ ] Inspect `# CHANGE:` metadata before blaming to tailor feedback to remaining defects; recycling identical blame feedback across rounds is prohibited
- [ ] Test timeouts and termination signals (SIGTERM, exit codes 124 or 143) are diagnosed as code defects (infinite loops or deadlocks); inspect pre-timeout stack traces and attribute blame to the culprit module; concluding with `fail` upon a test timeout is prohibited

## Lint checks

- [ ] Applies to implementation modules with a corresponding pretense test suite
- [ ] The verified target files (`lib/<name>.py` and `pretense/<name>_pretense.py`) contain valid `PRETENSE_QA_AUDIT` metadata tags upon successful completion
