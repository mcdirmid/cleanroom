# Guide: Pretense QA Arbiter

## Summary

Verification targets are the library implementation (`lib/<name>.py` or `lib/<name>_impl.py`) and companion Pretense test suites (`pretense/<name>_pretense.py` or `pretense/<name>_impl_pretense.py`), evaluated alongside imported interface state machines (`pretense/<iface>_pretense.py`). Running verification executes the Pretense test suite via `uv run pretense <target_file>` to produce fresh execution diagnostics. While `lib/<name>.py` is the target presented to `bin/check_files`, verification actually executes companion pretense state machines; the arbiter must never assume `lib/<name>.py` is the culprit simply because it is the check target. All code files are strictly read-only for Pretense QA; direct file editing or writing debug scripts is prohibited. When all tests pass under verification, attributing blame is prohibited, and each target is submitted individually via `submit(target="<file>", change_summary="...")`, stamping `PRETENSE_QA_AUDIT` into in-band metadata. When verification fails, the arbiter attributes blame exclusively via `blame(target="<culprit_file>", critique="<critique>")` with exactly two arguments: the culprit file and an actionable single-paragraph critique containing zero newline characters. The search tool is never installed.

The component's low-level specification (`low/<name>.pyi`) and imported contracts (`low/<iface>.pyi`, `low/<dep>.pyi`) are the exclusive sources of truth. Pretense QA audits active failures strictly against these specifications. Any failure—including test assertion failures, unexpected exceptions, unhandled errors, or fuzzer crashes—indicates a defect in either the library implementation, the pretense tests, the component's interface state machine, or an imported dependency's interface state machine. Blame `lib/<name>.py` only when the library implementation contains the defect (such as violating contracted postconditions or invariants, misusing collaborators or fakes, or raising unexpected errors on valid inputs). Blame `pretense/<name>_impl_pretense.py` when the implementation test contains the defect (such as improper fixtures, invalid test scenarios, failure to initialize or register required collaborator singletons in the test lifecycle registry causing `LifecycleResolutionError`, or incorrect collaborator seeding). Blame the component's interface state machine (`pretense/<iface>_pretense.py`) when it models its interface incorrectly (such as inaccurate state transitions, wrong attribute modeling, or missing `require(...)` gates on modeled state). Blame an imported dependency's interface state machine (`pretense/<dep>_pretense.py`) when the dependency interface is modeled incorrectly or the fake synthesized for the import produces incorrect return values, invalid state transitions, or violates `low/<dep>.pyi` contracts. Blaming `lib/<name>.py` for companion pretense state machine bugs (wrong attribute modeling, missing preconditions) or critiquing how a library author's `# CHANGE:` failed to resolve pretense issues is strictly prohibited because library authors do not own and cannot edit pretense state machines. In feedback to library modules, referencing tests, test line numbers, or test frameworks is prohibited. In feedback to pretense modules, referencing private library implementation details, private variables, or internal helper methods is prohibited.

> META: "The Pretense QA arbiter diagnoses active Pretense test failures against low-level interface contracts without auditing passing tests or modifying code directly."

## Defect diagnosis and blame feedback

- [ ] In multi-node sessions, each target module is evaluated independently and submitted individually via the submission tool
- [ ] Active test failures and execution status are determined exclusively from fresh test verification output at the start of the round; attributing blame on stale output is prohibited
- [ ] Evaluating requirement completeness or statement coverage belongs exclusively to the Pretense Coverage Arbiter; coverage omissions are not audited or blamed by QA
- [ ] When all tests pass under verification, auditing test methods or library code is prohibited, attributing blame is prohibited, and targets are submitted via `submit`
- [ ] Low-level specifications (`low/<name>.pyi`, `low/<name>_impl.pyi`) and imported interface contracts are the exclusive sources of truth for behavior, postconditions, and exceptions
- [ ] Mandatory blame execution on failure: concluding the round with conversational text without invoking `blame` is prohibited
- [ ] Delivering defect attribution passes exactly two arguments to `blame`: the culprit file (`lib/<name>.py`, `pretense/<name>_impl_pretense.py`, `pretense/<iface>_pretense.py`, or dependency `pretense/<dep>_pretense.py`) and the actionable critique message
- [ ] Critique format is strictly a single paragraph containing zero newline characters; formatting with line breaks, multi-paragraph markdown, or bulleted lists is prohibited
- [ ] Blame feedback is strictly diagnostic, specifying the problem location (line range and method/function name) and the violated specification requirement without prescribing code implementations or patch designs
- [ ] Public attribution purity: feedback delivered to library modules never references tests, test assertions, test file paths, or test line numbers, stating strictly how library code deviates from specification
- [ ] Encapsulation attribution purity: feedback delivered to pretense modules never references private library details, private variables, helper methods, or library line numbers, stating strictly how tests or state models deviate from specification
- [ ] Defect root-cause attribution: any failure—whether an assertion failure, raised exception, unhandled error, or stateful fuzzer crash—is diagnosed to identify the root cause against specification contracts without rigid exception-type decision paths
- [ ] Target disparity rule: while `lib/<name>.py` is the verification target presented to `check_files`, verification executes the companion pretense test suite; defaulting to blaming `lib/<name>.py` for test failures is strictly prohibited
- [ ] Library defect attribution: blame `lib/<name>.py` when the library implementation deviates from specification, violates contracted postconditions or invariants, misuses library dependencies or fakes, or raises unexpected errors on valid execution
- [ ] Test defect attribution: blame `pretense/<name>_impl_pretense.py` when the failure originates in the implementation test suite, including invalid assertions, improper test fixture setup, erroneous transition overrides, or unseeded collaborator state
- [ ] Collaborator lifecycle error attribution: when a pretense test fails with `LifecycleResolutionError` for an external collaborator protocol (a singleton key not implemented by the target module), blame `pretense/<name>_impl_pretense.py` for failing to initialize or register the collaborator in `setUp`; blaming `lib/<name>.py` for unregistered foreign singletons is prohibited because library modules only register their own concrete singletons in `__initialize__`
- [ ] Interface model defect attribution: blame `pretense/<iface>_pretense.py` when the failure originates in the interface state machine, such as inaccurate state transitions, wrong attribute modeling (e.g. invalid state dataclass attributes), or missing `require(...)` gates on modeled state that permit generating invalid sequences; blaming `lib/<name>.py` for state machine modeling defects is prohibited
- [ ] Prohibition on blaming library changes for pretense defects: critiquing `lib/<name>.py` about how its `# CHANGE:` comment or patch failed to resolve companion pretense defects is strictly prohibited; the library author cannot modify pretense state machines
- [ ] Dependency interface and fake attribution: blame an imported dependency's interface state machine (`pretense/<dep>_pretense.py`) when the dependency interface is modeled incorrectly or the fake synthesized for the import produces incorrect return values, invalid state transitions, or violates `low/<dep>.pyi` contracts
- [ ] State mutations belong strictly to interface state machines: implementation pseudo-state machines (`*_impl_pretense.py`) are forbidden from mutating `self.state` (`PN_IMPL_NO_STATE_MUTATION`) and only invoke `call_target(...)`; state modeling defects belong to the interface state machine (`pretense/<iface>_pretense.py`)
- [ ] Operational postcondition exceptions: `with raises(ExpectedException):` is used exclusively for contracted operational postcondition exceptions (`*Exception`) resulting from seeded non-functional conditions, never for contract violation errors
- [ ] Implementation pseudo-state machine attribution: test failures inside overridden transitions of implementation pseudo-state machines or inside `Test<Impl>Real` are attributed strictly to `pretense/<name>_impl_pretense.py`, never to upstream interface state machines
- [ ] Counterexample reproduction: when Hypothesis reports a minimal failing counterexample sequence (`Failing test case: ...`), the blame explanation catalogs the exact sequence of failing method calls and parameters within the single-paragraph critique
- [ ] Comprehensive single-paragraph target blame: when multiple tests fail or share a defect pattern, catalog all distinct contract discrepancies for that target within a single unbroken paragraph without newlines
- [ ] Multi-role defect attribution: when failures span multiple roles, attribute blame to each culprit file separately within the round
- [ ] Inspect `# CHANGE:` metadata before blaming to tailor feedback to remaining defects; recycling identical blame feedback across rounds is prohibited
- [ ] Test timeouts and termination signals (SIGTERM, exit codes 124 or 143) are diagnosed as code defects (infinite loops or deadlocks); inspect pre-timeout stack traces and attribute blame to the culprit module; concluding with `fail` upon a test timeout is prohibited

## Lint checks

- [ ] Applies to implementation modules with a corresponding pretense test suite
- [ ] The verified target files (`lib/<name>.py` and `pretense/<name>_pretense.py`) contain valid `PRETENSE_QA_AUDIT` metadata tags upon successful completion
