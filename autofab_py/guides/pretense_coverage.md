# Guide: Pretense Coverage Arbiter

## Summary

The pretense coverage arbiter evaluates statement coverage and contract postcondition completeness for an implementation unit (`lib/<name>.py` or `lib/<name>_impl.py`) against its companion Pretense test suite (`pretense/<name>_pretense.py` or `pretense/<name>_impl_pretense.py`) without modifying code files directly. Pure interface specification modules are excluded. Fuzz testing never explores contract violations, even if the error thrown is explicitly contracted. In fixed scenario tests used to establish statement coverage, checked preconditions that have a contracted Error with them (`PRECONDITIONS: - WHEN ... MUST raise ...Error`) must be reachable, verified by writing a sequence of transitions ending in a contract violation (throwing the specified Error via `require(..., error=...)` or `require_arg(..., error=...)`). Preconditions without errors define undefined behavior if violated and are assumed unreachable when uncovered in lib, handled with `from pretense import unreachable; unreachable()`, `# pragma: no cover (assumption: <reason>)`, or by restructuring code. Under `--no-fuzz --cov`, coverage is measured strictly across deterministic scenario test methods in the implementation Pretense test file; attributing implementation coverage deficits to upstream interface state machines is prohibited. When 100% statement coverage is achieved and all explicit contract postconditions are exercised, the target concludes via `submit(target="<target_file>")`, stamping `PRETENSE_COVERAGE_AUDIT: <timestamp>`.

Defect attribution is delivered exclusively via `blame`, formatted as a single paragraph without newlines in terms of the low-level specification. Line numbers can only reference the file being blamed. Blame delivered to the pretense module is strictly non-prescriptive, identifying only missing contracted specification postconditions, checked preconditions, or invariants without prescribing test code or mentioning internal symbols. Blame delivered to the library module is strictly restricted to reporting that code is unreachable under the contract; diagnosing functional bugs belongs to Pretense QA. When an uncovered span persists after the test author has updated tests or across multiple rounds, repeating blame against the pretense module is prohibited; the arbiter must inspect the library implementation, trace control flow, and attribute blame to the library module if the span is structurally or logically unreachable. If 100% coverage cannot be achieved without violating contracts, use `fail`.

> META: "The pretense coverage arbiter attributes uncovered lines to missing specification requirements or caller assumptions without modifying code files directly."

## Deficit diagnosis and blame feedback

- [ ] All code files (`lib/*.py`, `pretense/*.py`) are strictly read-only; defect attribution is delivered exclusively via the `blame` tool
- [ ] Uncovered statements are inspected by reading the library implementation file with line numbers enabled
- [ ] Fuzz testing never explores contract violations, even if the error thrown is explicitly contracted
- [ ] Checked preconditions with a contracted Error must be reachable in fixed scenario tests: blaming pretense modules to cover checked preconditions (`PRECONDITIONS: - WHEN ... MUST raise ...Error`) via terminal contract violation transitions is required
- [ ] Preconditions without errors are assumed unreachable when uncovered in lib, handled with `from pretense import unreachable; unreachable()`, `# pragma: no cover (assumption: <reason>)`, or code restructuring; blaming pretense modules to assert uncontracted caller precondition violations is strictly prohibited
- [ ] Blame feedback requiring `# pragma: no cover` must justify why the code is unreachable under `low/<name>.pyi` specification contracts or caller assumptions; instructing library code to pragma contracted operational branches is prohibited
- [ ] Contract postcondition audit: before submission, every explicit postcondition and grammar construct contracted in `low/<name>.pyi` is verified against the pretense scenario suite; if an explicit contract postcondition is unexercised, blame `pretense/<name>_impl_pretense.py` to add coverage even when statement coverage is 100%
- [ ] Blame feedback delivered to the pretense module is strictly non-prescriptive: it identifies only contracted postconditions, invariants, or positive-path branches lacking coverage, framed in terms of the low-level specification (`low/*.pyi`)
- [ ] Anti-contamination: blame feedback delivered to pretense never mentions library file names, line numbers, internal variables, private helper methods, or implementation artifacts
- [ ] Public boundary: blaming tests for failing to cover internal helper functions, private methods, or uncontracted defensive branches is strictly prohibited
- [ ] Implementation coverage attribution: under `--no-fuzz --cov`, coverage is measured strictly across deterministic scenario test methods in the implementation Pretense test file; attributing implementation coverage deficits to upstream interface state machines (`pretense/<iface>_pretense.py`) is prohibited
- [ ] Unyielding deficit reachability audit: when an uncovered span persists after a prior blame round or after the test author has modified tests, repeating blame against the pretense module is prohibited; the arbiter must inspect and trace the library implementation code (`lib/<name>.py` or `lib/<name>_impl.py`) around the uncovered span, analyzing conditional guards, loop invariants, preceding returns, and contract constraints to determine if the span is structurally or logically unreachable; if no conforming public API call sequence can reach the span, blame must be attributed to the library module to prune as dead code, mark with `from pretense import unreachable; unreachable()`, or annotate with `# pragma: no cover (assumption: <reason>)`
- [ ] Blame feedback delivered to the library module is strictly restricted to reporting that specific code is unreachable under the specification closure, instructing the library author to prune dead code, mark with `from pretense import unreachable; unreachable()`, or annotate with `# pragma: no cover (assumption: <reason>)`
- [ ] Functional defect prohibition: blame feedback delivered to the library module never diagnoses functional bugs, contract deviations, or algorithmic logic errors (functional defect arbitration belongs exclusively to Pretense QA)
- [ ] Defensive deadlock guards, loop stall breakers, and assertions protecting against infinite execution loops are safety guards rather than redundant dead code: blaming library code to delete defensive deadlock or stall guards is prohibited; such guards are covered by testing edge/failure conditions or annotated with `# pragma: no cover (assumption: <reason>)`
- [ ] Blame feedback format: the blame explanation string is strictly a single paragraph containing no newline characters or list formatting
- [ ] Target resolution and multi-role attribution: in multi-target sessions, the `blame` tool specifies the exact bound target file; when deficits span both roles, blame is delivered to each culprit file; delivering courtesy blame to the library when it contains no unreachable code is prohibited
- [ ] Auditor escape valve: if 100% coverage appears unreachable without either testing a precondition violation or deleting contracted behavior, use `fail`
- [ ] When 100% statement coverage is achieved and verified, calling `blame` is prohibited, and the target concludes via the `submit` tool

## Lint checks

- [ ] Applies to implementation modules with a corresponding pretense test suite (excluding pure interface definitions)
- [ ] Pretense test files pass pretense linter checks, containing no private member access or reflection on target classes or instances
- [ ] The verified target files (`lib/<name>.py` or `lib/<name>_impl.py`, and `pretense/<name>_pretense.py` or `pretense/<name>_impl_pretense.py`) contain valid `PRETENSE_COVERAGE_AUDIT` metadata tags upon successful completion
